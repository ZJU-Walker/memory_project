## 1. Executive summary

The original v3.4 objective was to make a recurrent Titans fast-weight memory write evidence
about which bin to open, retain it across reset/waiting, and make the policy use it later. The
first three runs developed a recurrent steepness / gradient-instability pattern. Run4 replaced
the effective learned per-episode output initialization with exact zero and was much more stable,
but at step 2400 it produced a real 5.21% severe-inner-clip window. A fixed-K/V
checkpoint-2250 replay reproduced a similar
tail and isolated carried momentum as necessary within that replay; it did not replay the exact
step-2400 batch. Run5 therefore kept current-gradient plasticity but set the previous-write
momentum contribution to exactly zero.

The v3.4.1/run5 result so far is mixed but useful:

- **Numerical stability is materially better.** Through the latest audited row (step 4900),
  there has been no NaN, OOM, CUDA/NCCL error, collapse, or watcher violation. Mean inner write
  gradient is about 1.45, memory-path outer gradient about 0.11, and severe clipping about 2.4%.
- **A rare steep tail remains.** Recent per-window maxima are commonly above 10 and have reached
  about 41. This is warning-only
  while the pooled severe fraction, mean, memory gradient, total gradient, and losses remain
  controlled. Eta-zero removed the old momentum amplifier; it did not prove that learned-core
  steepness can never return.
- **The evidence-frame online writer-head metric has weakly risen.** Its block accuracy rose
  from roughly 0.51 early to roughly 0.60 in steps 4100–4500.
  However, the head itself trains continuously, the writer CE remains near `ln(2)`, and the
  metric is training-stream only. This is encouraging writer-first evidence, not proof that the
  representation itself improved, committed to memory, survived, or controlled behavior.
- **Causal episodic-memory usefulness has not been demonstrated.** Raw and EMA causal token
  tests at checkpoints 500, 1000, and 2500 fail; raw and EMA action tests at 2500 fail. Replacing
  memory with an opposite-side donor does not make predictions/actions follow the donor.
- **A non-memory shortcut is already strong.** With a fresh/reset memory, the model still gets
  9–10 of 12 held-out waiting frames correct at checkpoint 2500, with large native-side
  candidate-sequence log-probability margins.
  Waiting arms are mostly stationary within an episode, but reset pose, images, collection
  order, and episode signatures are not side-neutral.
- **The next milestone should remain diagnostic, not architectural.** Continue the stable run,
  preserve checkpoint 5000, then separate online-head learning from writer-feature learning,
  run the four-rung writer/commit/read/retention ladder, localize the current-observation
  shortcut, and repeat the matched raw+EMA causal evaluation.

## 2. What is being trained

### 2.1 Base model and memory interface

Run5 starts fresh from the official `pi05_base` partial weight loader. The main model is pi05
with the v3.2 layer-8 dual-query memory interface:

- a top-camera layer-8 patch slice feeds a task-conditioned writer compressor; these features
  have already been contextualized by the early transformer and can contain image and state
  information;
- 16 raw write tokens are produced per frame;
- write tokens project to unit-normalized 512-dimensional keys and 2048-dimensional values;
- the memory is a per-sample fast-weight MLP with widths
  `512 -> 1024 -> 1024 -> 1024 -> 2048`;
- inputs and hidden activations use unit-L2 normalization;
- standard read queries are separately compressed and projected;
- retrieved memory is injected with the tanh/RMS-pinned path;
- the Titans gates are frozen at their initialized operating point.

Key implementation locations:

- `src/openpi/models/memory.py`
- `src/openpi/models/pi0.py`
- `src/openpi/training/config.py`
- `scripts/train.py`
- `src/openpi/transforms.py`
- `src/openpi/training/data_loader.py`

### 2.2 Fast-state recurrence

For already-projected keys and values, one write is:

```text
g_t = grad_M mean_i ||M_{t-1}(K_i) - V_i||^2
g_t <- clip_global_norm(g_t, 1)
S_t = eta_t * S_{t-1} - theta_t * g_t
M_t = (1 - alpha_t) * M_{t-1} + S_t
```

The frozen gate biases give approximately:

```text
theta = sigmoid(-2.2) ~= 0.10
eta_raw = sigmoid(2.2) ~= 0.90
alpha = sigmoid(-4.6) ~= 0.01
```

For v3.4.1/run5, `eta_effective = eta_scale * eta_raw = 0` on all hidden-token `write` and
`decay_step` paths. Each current clipped gradient still changes the fast state. The previous
write's momentum does not contribute to the next write. The state still records the current
`S_t = -theta * g_t`; “eta zero” means no dependence on `S_{t-1}`, not that the momentum tree is
always zero.

The explicit diagnostic API `write_kv(..., eta=...)` intentionally remains unscaled so offline
counterfactuals can supply exact eta values.

### 2.3 Blank episode initializer

Run4 and run5 set `MemoryConfig.blank_initial_output=True`.

- On every fresh episode, effective fast `w3` and `b3` are exact FP32 zero.
- Lower memory-MLP initializer leaves still come from learned `m0`.
- The outer/checkpoint `m0/w3` and `m0/b3` leaves remain in the parameter and optimizer tree for
  compatibility, but are disconnected from the effective episode initializer.
- Inner fast `w3` and `b3` remain writable; a memory write can make them nonzero and reduce
  own-key error.
- The optional trust-region origin uses the same effective blank initializer.

The canonical launch-provenance audit verifies this invariant at smoke checkpoint 120: raw and
EMA `m0/{w3,b3}` and their Adam `mu/nu` were exactly FP32 zero, while lower-layer controls were
nonzero and raw/EMA-distinct. Later selective spot checks at pilot checkpoints agreed, but those
checks are not part of the canonical launch-provenance bundle.

| masked modality | tokenized state digits only; images remain visible |
| memory blind tokens | enabled |

The comment in `pi0.py` saying a waiting label is decodable “only via evidence-phase writes” is
not enforced by the current objective. On a waiting frame, code writes the current observation
into `M_t` and then computes aux CE from `M_t`. A current waiting image/pose/episode cue can
therefore satisfy aux immediately. Main CE/action prediction for that same frame is computed
before the current write, although writes from earlier waiting frames can affect later waiting
frames.

### 2.5 Stability guards

| Guard | Value | Meaning |
| --- | ---: | --- |
| inner fast-gradient clip | `1.0` | per sample, before the fast update |
| recurrent-state cotangent clip | `10.0` | backward-only per-write state-chain guard |
| write K/V cotangent clip | `1.0` | backward-only guard toward writer/VLM inputs |
| memory-path outer gradient preclip | `5.0` | before the shared optimizer/global clip |
| optimizer global gradient clip | `1.0` | shared outer optimizer clip |

State and K/V cotangent guards are forward identities. Their existence does not directly bound
forward fast-state values, and current telemetry does not expose their bind rates.

## 5. Metric glossary: what each number does and does not prove

### 5.1 `diagnostic/ladder_writer_accuracy` and `_loss`

Implementation semantics:

- uses raw, pre-`W_K/W_V`, 16-token writer output;
- averages the tokens and L2-normalizes the feature;
- scores only unshifted evidence (`inspect both bins`) frames;
- the feature is `stop_gradient`;
- a separate linear head trains continuously with isolated constant-LR SGD (`0.01`);
- evaluated on the current raw training stream/head, not EMA and not the four held-out episodes.

It therefore measures **current writer feature plus current online head decodability**. It does
not measure projected K/V, the fast-state delta, own-key commit, retention, standard-reader
compatibility, or downstream use. The reported accuracy is micro accuracy, not balanced
accuracy.

Descriptive block means follow. Each entry is the arithmetic mean of five already frame-pooled
100-step ratios; it is not an evidence-frame-pooled 500-step estimate because the denominators
were discarded. Repeated frames/episodes and the adaptive head invalidate naive independent
confidence intervals.

| Steps | writer accuracy | writer CE |
| --- | ---: | ---: |
| 100–500 | 0.5076 | 0.6917 |
| 600–1000 | 0.5121 | 0.6928 |
| 1100–1500 | 0.5303 | 0.6902 |
| 1600–2000 | 0.5404 | 0.6905 |
| 2100–2500 | 0.5477 | 0.6895 |
| 2600–3000 | 0.5632 | 0.6866 |
| 3100–3500 | 0.5588 | 0.6890 |
| 3600–4000 | 0.5793 | 0.6868 |
| 4100–4500 | 0.5988 | 0.6878 |

The accuracy trend is encouraging for a writer-first milestone, but it is weak/noisy and not
monotonic. CE remains close to the uninformative balanced-binary reference `ln(2)=0.6931`; the
actual frame-micro class prevalence is not logged, so this is not a verified stream baseline.
The resumed CE slope is nearly flat. The incomplete step-4600–4900 block averages only about
0.576 accuracy, below the completed
4100–4500 block. Fresh, identically trained held-out probes at each checkpoint are the primary
way to test representation change. A cross-checkpoint head-by-feature factorial is secondary:
feature-coordinate rotation/drift can make transfer fail even when both heads are valid.
Moreover, the step-2500 resume retained the trained online head but recreated the seed-42 data
loader at the beginning of its stream. Post-resume observations therefore repeat early sampling
while the head and model continue learning, making accumulated-head learning or memorization an
especially plausible confound.

### 5.2 `diagnostic/ladder_read_accuracy`

This head sees mean-normalized standard retrieval on unshifted waiting frames, before the
current frame's write. It is also a detached online training-stream probe. It has no reset-M0
branch and its query is derived from the current observation. Read accuracy near 1.0 is therefore
not causal episodic-memory evidence.

### 5.3 `diagnostic/aux_side_accuracy`

This is grouped from the side-bearing shifted aux classes. Unlike the ladder, aux trains the
main system. Aux accuracy around 0.98–0.99 and falling aux loss prove that the post-current-write
memory-plus-head objective is solvable and supplies supervised pressure. They do not localize
that pressure to the writer/core, distinguish aux-head learning, or prove evidence retention,
because current waiting observations are written before aux is read.

The displayed scalar `loss` is also not a clean main-model objective: it includes both detached
online ladder CEs. Their gradients are later removed from the main Adam path and applied only to
the probe heads with isolated SGD. For example, the writer-head CE can dominate the displayed
loss even though it does not update the writer features.

### 5.4 Inner write telemetry

- `write_inner_grad_norm`: pooled mean raw associative inner-gradient norm before inner clip;
- `write_inner_grad_max`: true maximum over the logging window;
- `write_inner_clip_fraction`: fraction of valid writes with raw norm above 1;
- `write_inner_severe_clip_fraction`: fraction with clip factor below 0.2, equivalently raw
  norm above about 5 when the inner max norm is 1.

Severe clipping is a safety signal, not a learning metric. After clipping, raw norms 6 and 30
produce the same bounded current-gradient step length (up to direction). Useful learning does
not require severe events.

Run5 severe blocks rose approximately:

```text
steps 2600–3000: 0.01%
steps 3100–3500: 0.56%
steps 3600–4000: 1.86%
steps 4100–4600: 2.03%
```

At the same time ordinary clipping fell to roughly 57%. This looks like a small heavy tail, not
a global increase in write magnitude. Descriptively, over resumed rows 2600–4600, first
differences in severe fraction and writer accuracy were essentially uncorrelated (about -0.10),
while severe changes tracked inner mean changes much more strongly (about 0.74). The sample is
small and temporally correlated; these correlations are diagnostic, not inferential statistics.

### 5.5 Outer gradients

`memory_grad_norm` is a logging-window aggregate of the memory-path gradient before its group
preclip. It covers the whole configured memory path, including auxiliary components, so it does
not localize pressure to the writer or fast-memory core. `grad_norm` is a point sample taken once
per logging window after ladder gradients are removed and after the memory-group preclip, but
before the optimizer's shared clip. Do not call it an unrestricted raw total gradient or compare
it with `memory_grad_norm` as if they are same-batch peaks or both window averages.

## 6. Causal memory evaluation

Authoritative completed reports:

`diagnostic_outputs/v34_run5_causal/`

That root also contains aborted/incomplete directories. Treat only a report with its validated,
checksummed `COMPLETE` marker as authoritative; never aggregate `_aborted_*` or `INCOMPLETE`
outputs.

The evaluator `scripts/v34_causal_memory_eval.py` keeps raw and EMA sources separate. Raw is
restored from `train_state/params`; EMA comes from standalone `params`. At the exact held-out
waiting grids it uses pre-write current observations and matched RNG/noise across interventions.

Conditions include:

- production normal;
- same state with retrieved content zeroed;
- fresh M0 reset;
- never written;
- frozen before evidence;
- frozen after evidence;
- dynamics-only after evidence;
- same-task same-side donor swap;
- same-task opposite-side donor swap;
- reciprocal held-out opposite-side sensitivity swap.

Reset, never-write, and zero-read invariants pass exactly, so those three branches are wired
consistently. This alone does not validate every donor-swap branch.

## 7. Waiting-data and shortcut audit

The user is correct at the coarse physical level: most waiting segments show no intentional arm
motion. That rules down an obvious “active motion keeps writing the answer” explanation. It does
not make waiting observations side-neutral.

### 7.1 Within-episode stationarity versus cross-episode identity

At exact held-out waiting grids, within-episode state changes are small for most episodes. But
opposite-side held-out episode-mean reset states differ strongly when aggregated over the full
raw 14-D state, including both grippers:

```text
banana ep15-left vs ep29-right: RMS difference ~= 0.127, max coordinate ~= 0.243
pepper  ep44-left vs ep59-right: RMS difference ~= 0.085, max coordinate ~= 0.203
```

Exploratory leave-one-episode-out probes found side signal in absolute arm state and static
images. A simple top-camera downsample probe reached about 84% balanced accuracy in that audit;
state probes were around 71–75%, depending preprocessing. These are shortcut-existence screens,
not causal attribution of the trained model. They came from an ad-hoc read-only interactive
audit and do not yet have a persisted script/report artifact, so they must be rerun before they
are used in a publication or treated as reproducible evidence.

### 7.2 Collection confounding

Episodes were collected in strongly, but not perfectly, side-block-correlated order within each
instruction. For example, banana-right episode 7 interrupts the banana-left block
(`L=0–6,8–15`; `R=7,16–29`). Side is therefore plausibly confounded with slow camera,
background, calibration, reset-pose, and collection-time differences. Repeated nearly-static
frames can repeatedly expose the same episode signature.

### 7.3 Label anomaly

Training episode 26 lacks the expected final open-right phase. A long interval is labeled
`wait; target bin is right` while the right arm moves substantially. Under the exact
memory-critical endpoint sampler, most ep26 endpoints see that motion. Across the balanced
training cells, about 10.4% of memory-critical endpoints have current arm displacement above
0.02 radians, contributed by several episodes. The episode-26 anomaly is directly visible in
the data; the 10.4% aggregate is another unarchived exploratory calculation and should be
reproduced by a checked-in audit before formal use.

### 7.4 Ready but not yet run

`scripts/v34_waiting_shortcut_eval.py` is implemented and its 14 focused CPU tests pass. It is
pinned to run5 checkpoint 2500 raw/EMA sources and the exact 12 held-out waiting frames; the
intended current source is the checksummed diagnostic archive. It uses fresh M0 for every score
and matched RNG across:

- full observation;
- image-null;
- canonical-state-null;
- both-null;
- safe other-task controls;
- same-task opposite-side full/image-only/state-only swaps.

These interventions can conditionally localize evidence, but image/state nulls and hybrid swaps
may be out of distribution and cannot cleanly separate image, state, prompt, and interaction
effects on their own. Null ablations are corroborating only. The decisive gate is whether a real
same-task opposite-side observation swap makes the reset-memory output follow the donor with
adequate paired shift and frame/episode coverage. No completed GPU report exists yet. This
script is a trained-model shortcut audit; it does not reproduce the exploratory 84%, 71–75%, or
10.4% dataset calculations above.

## 8. Current hypothesis map

The observations do not identify one single remaining failure. The useful decomposition is:

1. **Writer representation failure:** raw evidence write tokens may only be weakly side-
   separable; the online rise may largely be probe-head learning.
2. **Commit failure:** write tokens may contain side, but projected K/V plus the clipped fast
   update may not store it accurately. Measure own-key readback versus V.
3. **Reader compatibility failure:** commit may work, but standard read queries may not retrieve
   the same content. The current online read head cannot distinguish this because it lacks a
   reset branch and sees current-observation-derived queries.
4. **Retention/interference failure:** valid content may be overwritten or forgotten between
   evidence and waiting. Current frozen/dynamics/normal results do not yet support this as the
   primary issue because side-specific content is not established upstream.
5. **Consumption failure:** memory may store/read something, but token/action pathways may ignore
   it. The action causal result is consistent with this, but earlier rungs must be proven first.
6. **Aux same-frame shortcut:** the aux objective may learn to write and decode the current
   waiting observation instead of preserving evidence.
7. **Non-memory shortcut:** current observation/prompt/episode signature already solves most
   waiting labels, removing pressure for the policy to depend on memory.
8. **Late learned-core steepness:** eta zero fixed the demonstrated carried-momentum amplifier,
   but the current 2% severe tail could plateau or become a later instability.
9. **Simply early training:** writer accuracy has a weak long-horizon rise through step 4500,
   but it is noisy and may be plateauing; the incomplete 4600–4900 block is lower. Later
   checkpoints could still develop causal utility, but existing metrics cannot assume that
   outcome.

## 9. Monitoring policy

The live watcher is `cluster_v34/watch_run4.py`, despite its historical filename. It is bound to
the exact numeric child step and never cancels the parent allocation.

Immediate exact-child stop:

- a missing required field, any malformed metric field, or any nonfinite parsed metric;
- write inner mean above 3;
- memory-path gradient above 5;
- severe fraction at or above 7.5%.

The numerical threshold gates start at step 100. Malformed or nonfinite telemetry remains
fail-closed even before that threshold start.

Marginal severe policy:

- 5–7.5% cancels only if the previous logged window was also at least 5%, or if the same window
  is corroborated by write mean at least 2.5, memory gradient at least 1, or total gradient at
  least 10.

Warnings only:

- severe fraction at least 3%;
- write mean at least 2.3;
- ordinary clip fraction at least 80%;
- any finite write maximum above 10;
- write mean above 2x the trailing-five median.

Scheduler uncertainty keeps the watcher alive. Failed cancellations are retried against the
same validated exact child. Manual reports were reduced to every 1000 steps; the on-node watcher
still reads each 100-step row without consuming conversation tokens.

## 10. Recommended next experiments, in order

Do not change the live training objective merely because the preregistered token/action grids
did not demonstrate causal utility at checkpoint 2500. The current writer-first question can
be answered more cleanly with diagnostics.

### 10.1 Localize the known reset-memory shortcut

Run the ready checkpoint-2500 waiting shortcut audit for raw and EMA. It can conditionally
localize current-image and state evidence with real opposite-side swaps, but OOD null/hybrid
conditions may leave mixed effects and should not be described as a clean modality separation.
It should be the first available-GPU diagnostic if it does not interfere with training.

### 10.2 Preserve checkpoint 5000

The checkpoint manager retains only one ordinary checkpoint except `keep_period=5000`. Confirm
5000 is atomically finalized and preserve a provenance-bound diagnostic copy if disk permits.

### 10.3 Separate writer-feature learning from probe-head learning

On identical evidence frames across archived checkpoints 500, 1000, 2500, and 5000:

1. extract raw writer features for raw and EMA separately;
2. train fresh standardized, class-balanced probes on non-held-out episodes;
3. test only held-out episodes;
4. choose standardization/regularization without the four held-outs, report every task-by-side
   cell, and include training-episode LOO/permutation nulls because four held-outs alone give
   only 0/4 through 4/4 accuracy resolution;
5. include label-shuffle and state/image baselines;
6. run a head-by-feature checkpoint factorial: head from checkpoint i on features from
   checkpoint j.

Fresh identically trained probes are the primary representation comparison. The factorial is a
secondary diagnostic only; coordinate rotation/drift can confound cross-checkpoint transfer.
Also test the actual projected K/V and individual slots, not only the mean raw token.

### 10.4 Run the exact four-rung ladder at checkpoint 5000

Stop interpretation at the first failing rung:

1. evidence raw writer / projected K/V decodability;
2. matched own-key commit: compare pre-write `||M_{t-1}(K_t)-V_t||` with post-write
   `||M_t(K_t)-V_t||`, not just a small post-write error;
3. post-write standard reader with the same state;
4. pre-write waiting retention versus reset M0 under the same queries.

The reader headline must be a paired same-query delta against reset M0. Do not subtract AUCs
from independently fit heads and call that a same-head causal delta. **The current ladder is
only a scaffold and must be fixed before this run:** it fits independent heads for reset/read
streams, restores EMA-only standalone `params`, and lacks causal-evaluator-grade provenance and
raw/EMA source handling.

### 10.5 Repeat the matched causal evaluation at checkpoint 5000

Run raw and EMA, token and action. Require donor-side swap specificity, evidence-write effects,
zero/reset confidence effects, and directional coverage. A normal-minus-reset confidence lift
alone is insufficient. **The current causal evaluator will reject checkpoint 5000** because its
origin validation is pinned to the pilot log that ends at 2500. Extend and test provenance
binding for the exact resume log before launching this evaluation; do not weaken the check.

### 10.6 Audit the severe tail at checkpoint 5000

Replay identical K/V with eta zero, stratified by position, phase, bucket, mask, episode, and
memory-critical flag. Log the exact offending samples and decompose residual size versus memory-
MLP directional gain and per-layer gradients. Escalate only if severe reaches the 3% warning and
continues toward 5–7.5%, or if mean/memory/total gradients corroborate it.

The existing incident replay is pinned to run4/checkpoint 2250, so it also must be adapted and
provenance-bound before it is used on run5 checkpoint 5000.

## 11. Conditional changes after localization

These are decision rules, not implemented v3.4.1 features:

- If writer rung fails: add an evidence-frame writer/contrastive objective. The current detached
  ladder cannot train the writer.
- If writer passes but commit fails: repair K/V projection, inner objective, or clipping/step
  geometry.
- If commit passes but standard read fails: align or condition reader queries.
- If standard read passes but waiting retention fails, and Dynamics-only passes while Normal
  fails: selective waiting write/freeze becomes justified.
- If every memory rung passes but token/action causal use fails: repair injection and downstream
  consumption.
- If the current-observation shortcut is confirmed: correct/counterbalance the data and change
  waiting aux timing or eligibility so it cannot be satisfied by a current-frame rewrite.
- If the severe tail develops into a multi-metric instability: stop the exact child and diagnose
  before adding another permanent clip. Do not interpret saturation as useful learning.

## 12. Evidence-quality corrections for future discussion

Claude should not inherit the following historical statements as established facts:

1. “Grad norm doubled every 100 steps” is an oversimplification. Run1 samples were noisy and
   nonmonotonic.
2. `grad_norm=212466` was a point sample, not a 100-step window average.
3. Historical `memory_grad_norm` values are window aggregates; they are not necessarily from the
   same batch as point-sampled total grad.
4. The old chain probe is a useful controlled stress test, not proof of a universal per-step
   state Jacobian. It used few batches, an arbitrary cotangent, and imperfect padding/boundary
   handling.
5. Exponentiating the median chain ratio does not reconstruct the reported total amplification;
   ratios were highly nonuniform.
6. The old fresh-drift comparison did not establish statistical identity. Raw
   `||M_t-M_0||` was dominated by passive alpha decay of large He-initialized hidden kernels
   toward zero; it is not a clean content-bloat measure.
7. Run1 and run2 did not log an inner-gradient time series. The claim that an inner-gradient
   ramp preceded both of those collapses is retrospective inference, not direct telemetry.
8. Online writer accuracy near chance does not prove no write-token information. It tests only a
   mean raw-token linear head and the head itself is adaptive.
9. Online read accuracy near 1 does not prove episodic recall. It lacks reset-M0 and held-out
   causal controls.
10. Waiting arms being reset/still does not prove the current observation is side-neutral.
11. Run4's step-2400 stop was watcher-requested under an obsolete threshold, not a spontaneous
    crash or full metric collapse.
12. A checkpoint directory named N contains internal TrainState step N+1 in these runs.

## 15. v3.4.1 leak fix 1: the static-waiting trim (2026-08-27)

Section 7 of this document listed the waiting-phase shortcut as "ready but not yet run".  It has
now been run, quantified, and the first of its fixes is implemented.  This section records the
audit result and the change; §7 and §10.1 remain accurate as background.

### 15.1 Audit result

`scripts/v34_leak_audit.py` (checked in, 3 CPU tests) is a model-free dataset audit; the
completed checkpoint-2500 GPU reports in `diagnostic_outputs/v34_waiting_shortcut/2500/{raw,ema}`
and `diagnostic_outputs/v34_waiting_camera_shortcut/2500/{raw,ema}` are the trained-model half.
Full write-up with figures: `diagnostic_outputs/v34_leak_audit/report.md`.

Three independent leaks, none of which requires episodic memory:

1. **Images.** Leave-one-episode-out ridge probes on waiting frames only reach 0.921 balanced
   accuracy pooled from the top camera alone (banana 0.855, box 0.929); left wrist 0.804.  The
   `|L - R|` mean-image heatmaps localize it to bin-lid rest positions, objects moved on the
   table between collection blocks, and arm rest poses.  Side is block-confounded with
   collection order, so session drift becomes side signal (held-out ep44 probes as RIGHT).
2. **State.** 0.704 pooled, driven by banana (0.831) where the LEFT arm was parked differently
   between the two sessions (L3/L4/L5 episode-mean |d| up to 2.9).  Box is near chance (0.558).
3. **Labels.** Episode 26 has no `open right bin` phase: frames 541-931 are labeled
   `wait; target bin is right` while the right arm performs the whole opening.  It is not alone
   -- a sampler-exact replay of all 4256 memory-critical endpoints found **17.1% with arm
   displacement > 0.02 rad** from the waiting reset pose, concentrated in episodes
   6, 9, 11, 21, 26, 28, 31, 45, 47, 53, 54.

The trained model takes the image path.  At checkpoint 2500, with memory fully reset, the
held-out native margin is +8.74 nats toward the correct side; an image-only swap from the
opposite-side episode moves it +17.5 toward the donor, while a state-only swap moves it -0.08.
Camera Shapley: left wrist +8.7 > right wrist +5.7 > top +3.4, with no single camera flipping
the answer alone.

Note also that the aux objective can be satisfied without retention at all: the scan step
commits the current frame's write *before* computing the aux CE from the post-write state, so on
a waiting frame the writer can transcribe the current (side-bearing) observation and aux reads it
back the same step.  That is fix 2 and is **not yet implemented**.

### 15.2 What fix 1 changes

New `DataConfig.memory_waiting_max_speed` / `memory_waiting_max_excursion` (None = disabled,
preserving every existing config).  When set, `data_loader._trim_waiting_to_static` keeps only
the longest contiguous run inside each episode's waiting phase over which no per-frame joint
step exceeds the speed cap and the total per-joint excursion stays within the excursion cap.

Sizing is measured, not guessed: the state stream quantizes at 3.8e-4 rad/frame and a typical
waiting phase drifts ~0.01 rad in total, so 4e-3 rad/frame is ~10x the noise floor and 0.02 rad
~2x the benign drift.  "Totally static" cannot be literal at this quantization.

Three consequences, all in the phase table so they share one source of truth:

* `memory_lo`/`memory_hi` tighten, so **memory-critical endpoints can only land on static
  frames**;
* `memory_critical_ok` marks episodes whose static core cannot hold one grid step (only ep22);
  their phase bounds stay accurate for the slice dead zone, but no endpoint may be placed there;
* `episode_waiting_valid` per-frame booleans flow through `MemorySequenceSubtasks` as
  `subtask_valid` / `subtask_now_valid` and are consumed by `MemoryV34Labels`, which sets the aux
  target to -1 (masked out of the class-balanced CE), drops the frame from the ladder waiting
  mask, and suppresses the plan-5.2 state-mask draw for segments left with no valid waiting
  target.

Observations and actions on dropped frames still train the policy normally -- only the *memory*
supervision is withdrawn.  Main-CE subtask labels are left exactly as the dataset states them;
no label is invented.  Consequently ep26's mislabeled tail still supervises the subtask head on
normal slices, which is a residual data-quality issue rather than a memory leak.

Measured effect over all 60 episodes: 39 trimmed, 654 waiting frames (1.2% of all frames)
dropped from memory supervision, median waiting window 59 -> 51 frames, ep26 391 -> 54.  Head
trims matter as much as tail trims -- the waiting label often starts while the arm is still
settling out of the reset (ep21 -44, ep59 -23, ep28 -20, ep47 -19, ep16 -17).

**Acceptance test** (`scratchpad verify_endpoints`, reproducible from the config names): the
fraction of memory-critical endpoints with arm displacement > 0.02 rad goes
**17.11% -> 0.00%** (max displacement 1.739 -> 0.018 rad), at a cost of 76 of 4256 endpoints.
